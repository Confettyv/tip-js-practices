# История изменений

Формат: одна версия — один раздел, записи описывают поведение, которое видит
пользователь или эксплуатация. Нумерация по смысловой модели X.Y.Z.

## 1.0.0 — 2026-11-02

### Добавлено

- `GET /health/live`: процесс отвечает 200 и не обращается к PostgreSQL.
- `GET /health/ready`: 200 и версия выпуска, если база отвечает; 503 `not_ready` без
  внутренних деталей, если нет.
- Журнал в формате JSON Lines: одна строка на событие, уровни `debug < info < warn < error`.
- Запись `http_request` по каждому ответу: request id, метод, путь без query string, статус,
  длительность по монотонным часам. Статус 4xx пишется как `warn`, 5xx как `error`.
- Заголовок `X-Request-Id` в каждом ответе. Входной id клиента принимается, только если
  это 1–64 символа из `A–Z a–z 0–9 . _ -`, иначе сервер выдаёт свой UUID (вариант 1).
- Скрытие `password`, `authorization`, `cookie`, `connectionString` в журнале на любой
  глубине и в любом регистре.
- Корректная остановка по SIGINT и SIGTERM: новые подключения не принимаются, текущие
  запросы завершаются, затем закрывается pool. Предел 10 с, повторный сигнал не запускает
  закрытие заново.
- Новые переменные `API_HOST`, `NODE_ENV`, `LOG_LEVEL`, `RELEASE_VERSION` с проверкой значений.
- Production-образ (Node 24 alpine, пользователь `node`, только production-зависимости) и
  запуск API + PostgreSQL 17 через Docker Compose с named volume.
- Workflow GitHub Actions: PostgreSQL service, `npm run release:check`, сборка образа.
- Smoke-проверка работающего экземпляра: `npm run smoke`.

### Изменено

- Сообщения запуска и ошибок стали структурированными событиями (`server_started`,
  `server_start_failed`, `shutdown_*`) вместо свободного текста в консоли.
- API слушает адрес из `API_HOST` (в контейнере `0.0.0.0`), а не жёстко `127.0.0.1`.
- CORS разрешает клиенту отправлять и читать `X-Request-Id`.
- Непредвиденная ошибка по-прежнему даёт клиенту общий 500, но теперь пишется в журнал
  событием `unhandled_error` с request id (без стека и тела запроса).

### Исправлено

- Недоступная база давала 500 вместо 503: ошибки подключения Node и драйвера pg
  (`ECONNREFUSED`, сбой DNS `ENOTFOUND`/`EAI_AGAIN`, таймаут подключения пула, обрыв
  соединения) не имеют SQLSTATE и не распознавались.
- `npm run smoke` всегда падал с 400: проверка запрашивала `/api/tasks?limit=1`, а API
  отклоняет неизвестный параметр `limit`. Теперь запрос `?completed=false`.
- `API_PORT=05505` принимался как 5505: число с ведущим нулём теперь отклоняется.
- `ENABLE_DEBUG_RESET=true` при `NODE_ENV=production` теперь останавливает запуск: маршрут
  полного сброса данных не может оказаться включённым в production.
