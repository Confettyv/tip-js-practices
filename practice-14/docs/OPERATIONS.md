# Эксплуатационная памятка

Версия 1.0.0. Команды выполняются из корня проекта. Пароль хранится только в `.env`,
в журналах и выводе команд ниже его нет.

## Запуск

Контейнеры (API + PostgreSQL):

```bash
cp .env.example .env          # заменить оба CHANGE_ME одним паролем
docker compose up --build -d
docker compose ps             # db: healthy, api: healthy
npm run smoke                 # SMOKE_BASE_URL, если порт не 5505
```

Локально, с уже работающей PostgreSQL:

```bash
npm ci
npm run db:prepare            # только для новой пустой базы: схема + seed
npm start
```

База инициализируется скриптами `sql/` один раз, при первом создании volume. Повторный
`up` их не выполняет и данные не трогает.

## Проверка состояния

| Запрос              | Норма                                | Что значит отказ                       |
| ------------------- | ------------------------------------ | -------------------------------------- |
| `GET /health/live`  | 200 `{"status":"ok"}`                | процесс завис или не запущен           |
| `GET /health/ready` | 200 `{"status":"ready","version":…}` | 503: база недоступна, запросы не слать |
| `docker compose ps` | оба сервиса `healthy`                | смотреть журнал сервиса                |

Healthcheck контейнера API обращается к liveness, поэтому отказ базы не делает API
`unhealthy` и не перезапускает его. Готовность отдельно показывает readiness.

## Остановка

```bash
docker compose stop api       # SIGTERM, корректное завершение до 10 с
docker compose down           # контейнеры удаляются, volume с данными остаётся
```

Локально `Ctrl+C` (SIGINT). Второе нажатие завершает процесс сразу, если корректная
остановка зависла. Успешная остановка оставляет в журнале `shutdown_completed`.

## Резервирование и восстановление

Копия учебной базы из контейнера (файл без пароля, но с данными: в Git не добавлять):

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' > backup-tip.sql
```

Восстановление в ту же базу (текущие строки будут заменены содержимым копии):

```bash
docker compose stop api
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' < backup-tip.sql
docker compose start api
```

Перед восстановлением сделать свежую копию текущего состояния. Проверка результата:
`npm run smoke` и чтение нескольких записей через API.

## Диагностика

| Симптом                                          | Проверка                                                                                              | Безопасное действие                                                                   |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `/health/ready` отвечает 503, `/health/live` 200 | `docker compose ps db`, `docker compose logs --tail=50 db`                                            | запустить `docker compose start db`, дождаться ready; API перезапускать не нужно      |
| API не стартует, в журнале `server_start_failed` | поле `message` события: переменная `.env`, `EADDRINUSE`, отказ базы                                   | исправить названную переменную или освободить порт, затем `docker compose up -d`      |
| Клиент получает 500                              | найти в журнале `unhandled_error` по `X-Request-Id` из ответа: `docker compose logs api \| grep <id>` | воспроизвести запрос на копии данных, исправить и выпустить patch-версию              |
| Запросы медленные                                | `durationMs` в записях `http_request`, `docker stats --no-stream`                                     | сравнить с readiness; при нехватке памяти остановить лишние сервисы, не удаляя volume |
| После `up` нет данных                            | `docker volume ls`: совпадает ли имя проекта Compose с прежним                                        | запускать из той же папки или с тем же `-p`; volume не удалять                        |
| `docker compose up` требует `POSTGRES_PASSWORD`  | `.env` рядом с `compose.yaml` и строка `POSTGRES_PASSWORD=`                                           | создать `.env` из `.env.example`                                                      |

**Внимание.** `docker compose down -v` удаляет volume, то есть все данные базы. Это не
способ остановки. Применять только к учебному проекту после проверки имени проекта
(`docker compose ls`) и свежей резервной копии.

## Известные ограничения

- Один экземпляр API и одна база на одной машине: нет реплик, балансировщика и TLS.
- Аутентификации нет: любой, кто видит порт, может менять задачи. Порт не публиковать
  за пределы локальной сети.
- Журнал пишется в stdout контейнера и хранится, пока существует контейнер; ротацию и
  сбор журналов настраивает платформа.
- Миграций нет: схема создаётся один раз при новом volume, изменение схемы требует
  ручного скрипта.
- Readiness ждёт ответ базы до таймаута подключения pool (3 с), отдельного предела нет.
