## Модель и контракты

Задача: `{ id, title, completed, priority }`.

- `id`: число, `Number.isSafeInteger(id) && id > 0`. Строка `"4"` не превращается в 4.
- `title`: строка, после `trim()` от 1 до 100 символов; сохраняется очищенной.
- `completed`: только `true`/`false`; новая задача всегда `false`.
- `priority`: `"low" | "medium" | "high"`, по умолчанию `"medium"` (только при `undefined`).

Проверки собраны в три функции `validateId`, `validateTitle`, `validatePriority`,
каждая возвращает текст ошибки или `null`. В `createTask` они соединены через `??`:
первая найденная ошибка и есть результат.

| Функция | Успех | Отказ |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект (не копия) | `undefined` |
| `getPendingTasks`, `getTaskTitles` | новый массив (`filter`, `map`) | — |
| `getTaskStats` | `{ total, completed, pending, progress }`, progress не округлён | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks }` с новым массивом | `{ ok: false, error }` |

Операции изменения устроены одинаково: `checkExisting` проверяет `id` и наличие записи,
дальше `addTask` строит `[...tasks, task]`, обновления идут через `map` и
`{ ...task, поле }`, удаление через `filter`. Входной массив и его объекты не меняются
никогда; новый объект создаётся только для выбранной записи, остальные переиспользуются.

**Почему `id` не индекс.** После удаления индексы сдвигаются, а `id` остаётся за
задачей. В наборе `id = 4` стоит по индексу 1, и поиск по `id = 4` должен вернуть именно
её, а не `tasks[4]`.

**Почему `progress` число.** Это данные для расчётов и проверок. `toFixed(1)` даёт строку,
поэтому вызывается только при выводе в `main.js`.

**Что копируется.** Массив целиком (новый) и одна изменяемая запись (новый объект через
spread). Если бы копировался только массив, как в эксперименте 4, изменение поля
испортило бы исходный объект.

## Расширение: поиск по названию

`searchTasks(tasks, query)`: запрос очищается `trim()` и приводится к нижнему регистру,
отбор через `filter` и `includes`, порядок сохраняется. Пустой запрос даёт новый массив
всех задач, потому что любая строка содержит `""`.

| Запрос | Ожидание | Факт |
|---|---|---|
| `" ФУНК "` | `[1]` | `[1]` |
| `"ПОДГОТОВИТЬ"` | `[4]` | `[4]` |
| `"ть"` | все четыре | `[1, 4, 7, 10]` |
| `"несуществующий фрагмент"` | `[]` | `[]` |
| `"   "` | новый массив всех задач | равен исходному, но `!==` |
| поиск в `[]` | `[]` | `[]` |

Записи после поиска равны исходным (А4).

## Вывод

В ПР1 значения считались и сразу печатались. Здесь расчёт и вывод разделены: функции
возвращают данные (`{ ok, task }`, `{ ok, tasks }`, сводку числом), а `main.js` решает,
что показать. Ожидаемые ошибки тоже стали данными, поэтому отказ не обрывает сценарий и
не портит текущее состояние. Неизменность проверялась сравнением со свежей копией
исходных данных и ссылками (`===` для нетронутых записей, `!==` для изменённой);
порча кода показала, что проверки это действительно ловят. Исправленная ошибка —
пропущенный `return` в стрелочной функции с фигурными скобками.
